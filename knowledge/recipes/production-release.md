# 发布前检查与导出失败定位

适用：编辑器能跑，但独立包黑屏、缺资源或保存失败。

方案 A：先发布一个已具备工具链的平台，验证真实交付；方案 B：同时铺多个平台，会增加输入、渲染、包配置与设备验证成本。原型阶段先选 A。

做法：记录引擎版本、模板版本、导出预设与目标目录。把“缺模板”“平台 SDK 未配置”“资源缺失”“启动逻辑报错”分开定位，不因为一项缺失就重写游戏。

验证清单：从干净目录启动包、默认分辨率与缩放、输入、音量偏好、首次存档、重启恢复、缺失动态资源、错误日志。独立包与编辑器各记录结果。

边界：Android/JDK/SDK 和 Web/C# 的支持状态要查当前版本官方平台文档；本机没有工具链时标为未验证，不凭编译成功宣称可发布。

异常退出时，先保留原退出码，再收集文件日志；不能只在成功分支读取日志。日志缺失、读取失败或截断均应明确标记，不把空日志解释成没有错误。已生成EXE不等于启动通过，也不等于可交给玩家。

工作台重启后，未完成的构建记录不代表原构建已停止。原宿主仍在或无法确认时，不重复生成，也不从新窗口假装取消原任务；原宿主已退出仍不能推断游戏子进程已经结束。先核对原窗口和记录，再决定下一步。具体工作台实现与限制见[当前交付状态](../../docs/当前交付与剩余验收.md)，不是其他工具的通用进程管理保证。
