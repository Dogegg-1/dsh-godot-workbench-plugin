# 背包与购买的原子结算

适用：买东西扣钱没到账、背包满仍扣钱、连点得到重复物品。

方案 A：小型单机项目使用同步领域函数，在内存一次验证并提交；成本低。方案 B：多步骤或异步交易引入事务记录和幂等 ID，恢复能力更强但工程复杂。别为简单同步购买先搭通用交易服务。

做法：把 UI 变成请求发起者；领域层计算最终价格、余额与容量，不信任界面缓存的旧价格。先构造候选状态，全部条件通过才替换原状态并发出事件。

算例：余额 10、价格 10、容量剩 0，应保持余额 10 和原库存；不能先扣为 0 再发现放不下。

验收：刚好够钱、差 1、零价/负价拒绝规则、连点、商品在请求期间下架、达到资源上限。存档与 UI 刷新都读取提交后的状态。
