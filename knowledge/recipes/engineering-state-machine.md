# 状态机与非法状态组合

适用：is_attacking、is_dead、is_stunned 等布尔值出现相互矛盾组合。

方案 A：枚举加集中转移函数，3 至 6 个状态通常便于阅读，但多角色复用成本上升。方案 B：独立状态对象，适合复杂复用，但增加对象生命周期与调试入口。状态数量只是选择线索，不是硬门槛。

做法：画出允许的转移表，进入/退出动作只在转移时执行。定义同帧死亡、受击、攻击结束的优先级，避免多个回调各改一半状态。

例：Idle→Attack→Recovery→Idle，任何活状态可→Dead；Dead 不得因旧动画回调回到 Idle。用执行代号或当前状态核对迟到回调。

验收：逐条测试允许和禁止转移；暂停、重生、场景卸载时清理计时器与监听。此为原创工程配方，具体 API 另行查证。
